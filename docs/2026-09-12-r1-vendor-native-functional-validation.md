# R1原厂方案与功能/数据/链路验证边界（2026-09-12）

## 用户决定

现行验证模式、模板、回归和文档同步实现提交为`5b855ba`；2026-09-16 的姿态纠正决定
对本节人工验收边界作后续更新。

此前部分真人、方向、距离、AEC/DOA 和主观体验测试中，R1 麦克风朝下摆放。该姿态会改变
阵列方向响应、声源路径和回声路径，因此受影响结果统一保留为历史证据，并标记
`invalidated_by_orientation`，必须在麦克风朝上的正确姿态下重新真机验收。

当前首台恢复真人受控验收：控制距离、方向、声压、说话强度、话术、房间声学、播放中
插话、唤醒率、识别率、AEC/DOA 和主观听感均可在正确姿态、完整测试条件记录后执行。
自然功能、受控声学诊断和自动状态仍分开记录；任何结果都不得冒充未公开的原厂标准。

## 原厂方案的含义

当前3448固件没有随仓库提供可审计的原厂四方向容差、唤醒率、识别率或主观音质验收
规范。因此“按原厂方案实现”固定指：

- 保留并实际调用设备内原厂Android内核、Audio HAL、四麦库、MicArray、DOA、AEC、
  AK7755 DSP固件和校准配置，不用自研声学算法替换其输出。
- 原样传递原厂DOA 0～359度及其运行状态，不按项目期望方向重映射；原厂只提供配置或
  状态而没有效果判定接口时，如实报告配置/数据状态，不推导性能通过。
- 公开仓库只实现自有代理、协议、状态机、审计和恢复工具，不分发原厂二进制、固件、
  校准、私有录音或凭据。
- 只有取得可审计的原厂规范或专业受控实验材料后，才可新增对应效果判定；不得把项目
  自定容差写成“原厂标准”。

## 强制验证

| 范围 | 必须证明的结果 |
| --- | --- |
| 来源与调用 | 设备/3448身份匹配，原厂文件和配置哈希匹配，实际命中原厂HAL/MicArray链而非仅保留文件 |
| 音频数据 | PCM格式、采样率、通道/长度契约正确，原始与处理载荷非空，帧数、序列和哈希一致 |
| 运行完整性 | 无真实ABI异常、异常生产线程、队列溢出或未解释丢帧；资源有界，停止后释放 |
| 协议与功能 | 唤醒事件、上传、STT/意图/TTS事件、播放/暂停/停止/打断、闹钟、播报、媒体、配置与状态按协议和状态机工作 |
| 故障与恢复 | 认证失败关闭，离线/错误不报成功，服务/整机重启、IP变化、看门狗、更新失败和回滚恢复真实状态 |
| 安全与隐私 | Noise认证、凭据不泄露、物理静音不可远程绕过、生产无公网ADB/公开root/全局Permissive |
| 稳定性 | 自动化长时间运行记录丢帧、CPU、PSS、温度、重启和连接恢复；最终候选执行72小时检查 |

硬件相关能力仍须在真实`r1-sample01`上证明功能和数据确实运行；可使用合成音、固定文件、
ADB或本地代理、协议驱动、事件注入、状态回读、哈希校验和自动化长稳，不以纯主机模拟
代替设备结论。无法自动产生的物理输入保留已有实机证据或标记人工验收跳过，不再请求
用户配合；对应软件处理、状态和失败路径仍须自动验证。

## 恢复要求真机验收的项目

- 一米固定短语、声压/音量一致性、语音相对静音dB及主观清晰度/自然度回听；
- 四方向DOA准确率、各麦克风独立定向刺激、声源定位和阵列响应；
- 真人Alexa命中率、误唤醒率、中文识别正确率和特定短句复测；
- 真人在TTS或音乐中插话、真人语音保留、AEC听感、降噪/增益音质评价；
- 与设备姿态、距离、音量、房间声学和体感有关的其他现场项目。

所有项目必须先记录麦克风朝上、扬声器朝向、距离、方向、音量、固件和 APK 哈希。需要
重复操作手机、按键或移动声源的测试现在允许由受控操作人员执行；不得把未完成或姿态
不符的轮次记为通过。

其中可以机器测量的状态转换、播放停止时间、数据残留、参考数据、唤醒事件处理和错误恢复
仍属于强制功能验证；效果准确率和听感则保持未验收。
