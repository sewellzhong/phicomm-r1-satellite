# r1-sample01 免拆分级授权与验收边界（2026-09-11）

## 用户决定

首台 `r1-sample01` 始终采用免拆路线：不打开机壳、不短接、不焊接，也不把物理
Maskrom作为开发或交付前提。目标是在该约束下完成既定单台功能；复杂、耗时或需要更高
Android权限不构成停止理由。

以下两项改为非强制能力，不阻塞其他功能交付：

- 电气硬断麦：能够在免拆条件下证明并实现则保留，否则不要求切断麦克风供电或模拟信号
  线路。必须交付实体按键触发的强制软件静音：特权层停止采集，远程入口不能解除，状态与
  灯效如实同步，重启后保持；没有电气证据时不得称为“硬件断麦”。
- 所有引导组件损坏后的恢复：能够在免拆条件下增强则继续增强，但不要求在 boot、recovery、
  Loader等同时损坏时仍可恢复，也不以故意破坏全部引导链作为验收测试。

## 当前分级授权

本授权只绑定首台 `r1-sample01` 及当前固件 3448 基线。设备或固件变化时必须重新盘点并
重新取得授权。R0继续为 `pending`；风险接受不等于完整eMMC、独立恢复入口或受控完整回刷
已经通过。

在确有功能或验证需要、且较低权限路线已有可复现实机证据证明不足时，无需再次确认即可：

- 使用Android root、补丁或定制boot、必要的system/recovery修改、特权系统服务、最小原厂
  服务桥及专用SELinux策略；
- 管理、停用或替换冲突系统包，运行时挂载自有组件，以及刷写精确命名的boot、system或
  recovery分区；
- boot优先只改ramdisk中的自有代理、init和策略；若实机证据证明kernel/DTB是完成既定功能
  的必要条件，可在同一boot分区内制作独立候选并按相同门禁验证。

生产镜像必须保持SELinux Enforcing。此决定不授权全局Permissive、公开root入口或公网ADB，
也不允许在源码、APK、日志或示例中保存凭据或分发原厂材料。

以下操作仍须在发现确有必要后提交证据、范围和风险，另行取得用户明确授权：

- 修改Loader、参数/分区表或物理首4 MiB；
- 擦除、格式化、整盘/整段eMMC覆盖写入；
- 对其他设备或变化后的固件复用本授权。

## 每次高风险操作的门禁

分级授权不是无条件写入许可。每个目标分区首次或再次写入前都必须：

1. 核对ADB序列、设备ID、完整fingerprint、分区名、物理地址和长度。
2. 从当前设备读取目标分区两次，逐字节或SHA-256一致，并保留两份原始输入及来源记录。
3. 固定候选、构建工具、风险记录和预期哈希；不得同时夹带未获授权的分区修改。
4. 单次写入后、复位前完整读回并匹配候选哈希；任一身份、地址、长度或哈希不符立即停止。
5. 启动后核对Android、ADB、SELinux Enforcing、网络、音频及本次涉及的功能；失败如实记录，
   不把人工恢复或风险接受写成R0通过。

system和recovery写入工具尚未因此自动具备或获验收；真正需要时须先实现与boot写入同等级的
失败关闭门禁并完成主机测试，再进入实机窗口。

## 功能与更新验收

- 原厂四麦、MicArray、DOA、AEC和DSP仍按R3实机指标验收。boot代理不足时依次使用本决定
  允许的最小system/recovery路线，不自动退回标准AudioRecord或降低指标。
- 签名更新与回滚必须覆盖APK、模型和自有用户态组件，包括版本、SHA-256、签名、健康检查
  和失败回退。boot/recovery更新仍执行备份、读回及人工可达恢复检查，但不承诺所有引导
  组件同时损坏后的自动恢复。
- 所有既定功能继续区分代码支持、主机测试和真实R1验收。若免拆路线出现不可实现的硬件
  限制，必须提交可复现证据和影响，由用户决定后续处理；不得静默删减功能或宣称完成。

本决定取代2026-09-10 boot-only风险豁免作为后续开发的现行授权边界，但不改写当日实验的
历史范围、结果和证据。
