# R1 更新监督器包替换编排主机记录（2026-09-13）

## 本轮范围

在U2持久事务与候选落盘基础上，实现可替换的包管理后端契约和主机可验证的更新/回滚编排。受测实现提交为`e6720cea04fa45c520adc5e6567efe464093da3c`。

本轮没有连接R1、ADB或HA，没有构建或安装设备APK，也没有调用真实Android PackageManager。主机伪后端只验证副作用调用顺序、持久状态和失败关闭行为，不作为3448固件安装或回滚证据。

## 已实现边界

- `PackageManagerBackend`只暴露固定包身份读取、归档身份读取、旧包备份和带显式降级标志的归档安装；不接受shell命令或参数字符串。
- 编排器在调用后端前验证固定生产包名、32位小写十六进制操作ID，以及候选路径、长度和SHA-256必须与U2落盘结果完全一致；客户端构造的操作ID不能形成任意路径读取。
- 更新顺序固定为：独立读取当前包与候选归档身份，持久化`staged`，备份旧包并从备份再次读取完整身份，持久化`installing`，安装候选，再独立读取已安装包。包名、版本、APK哈希或签名任一不匹配均不进入健康等待。
- 只有候选身份完整匹配后才进入四项健康门闩。服务、持久状态、原厂音频代理和原包隔离必须全部健康；部分健康、身份读取失败、超时和确认前重启均请求回滚。
- 安装失败或健康探测失败先把`rolling_back`原子持久化，持久化失败时禁止调用降级后端。旧包安装后还要独立回读来源版本、旧APK哈希和签名；回读不符或降级失败保持`failed`。
- 监督器在`installing`阶段崩溃后只恢复为回滚并安装已经固定的旧包备份，不重试结果不明的候选安装。备份失败发生在任何包替换之前，安全取消`staged`事务。

## 主机故障注入

新增伪后端测试覆盖：

- 正常备份、候选安装、四项健康确认和事务清除；
- 备份内容损坏时安装零调用；
- 非法操作ID在任何后端调用前拒绝；
- 候选安装失败后降级并回读；
- 安装后身份不符及部分健康时降级；
- `installing`事务重启后只执行降级；
- 降级失败保持`failed`；
- 回滚状态无法持久化时不执行降级副作用。
