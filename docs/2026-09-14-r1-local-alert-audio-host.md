# R1本地闹钟音乐与自定义计时提示主机实现（2026-09-14）

## 范围与语义

用户新增要求：闹钟到时播放音乐；计时器到时必须播放声音且内容可自定义。本实现把任意
内容固定为R1支持的PCM S16LE、16 kHz、单声道WAV，可使用音乐、提示音，或由HA TTS预先
生成的自定义语音。内容在配置时经认证Noise链路同步到R1应用私有目录；到时只读本地文件，
不依赖HA、DNS、URL或网络在线。

本轮不把主机测试写成实机通过。真实R1仍须验证上传、哈希回读、断网/重启后播放、循环、
停止、稍后提醒、DND、媒体抢占、损坏降级和清理。

## 设备端

- 新增`alert_audio`认证服务，使用固定请求/响应关联ID；单块最多4 KiB，严格连续offset；
- `begin`绑定内容ID、总大小和SHA-256，`commit`再次实算哈希并校验WAV后使用POSIX原子rename；
- 单文件44字节～16 MiB，最多64项且总计不超过64 MiB；ID仅允许小写字母、数字、`_`、`-`；
- 只接受PCM S16LE、16 kHz、单声道WAV，拒绝路径逃逸、乱序、重复、超限和格式不符；
- 闹钟持久化schema由2升到3并兼容读取schema 1/2，每项新增`sound_id`；
- 计时器使用全局`timer_sound_id`，闹钟逐项使用`sound_id`；内容循环播放直至停止；
- 正在被计时器或任一闹钟引用的内容拒绝删除。内容缺失/损坏时使用原`classic/gentle/urgent`
  合成声音兜底，并通过实际输出mode和降级计数回报，不把本地音乐误报为已播放。

## HA与语音入口

HA集成版本提升到0.16.1。管理员把已转换WAV放在
`/config/r1-alert-audio/`，通过本地闹钟实体的`alert_audio_upload`服务上传；路径被限制在该
目录且拒绝符号链接。服务可在上传后直接绑定计时器，也可分别绑定/删除。R1回读ID、大小和
SHA-256全部匹配后才反馈成功。

闹钟`alarm_put`新增`sound_id`，离线pending、冲突检测和分页状态同步同一字段。中文入口可按
已缓存ID设置或恢复闹钟音乐、计时器提示音；不存在的ID不写入。ID当前是稳定配置标识，音乐
标题等展示别名留后续UI增强，不影响本地播放门槛。
