# v107 闹钟认证同步与 HA 全量视图主机记录

日期：2026-09-12

## 结论

v107 在 v106 本地闹钟内核之上实现固定 ESPHome Native API 版本内的闹钟同步扩展，并在
`r1_input_guard` 0.7.0 增加 HA“本地闹钟”实体和创建、删除、启停、停止、稍后提醒、刷新
实体动作。所有操作通过既有 Noise PSK 连接；设备响应包含随机请求 ID、操作类型和本地
存储完整回读，HA 只有校验响应并收齐同一版本的全部分页后才更新确认状态。
源码提交为 `493e14f4db49a37473a9b89ca841601937569c6d`。

本轮是代码和主机验证，不是实机或生产 HA 验收。离线时 HA 保留最后确认列表、把实体标为
不可用并拒绝把修改反馈为成功；尚未实现离线待同步写队列，也未接入中文语音创建/查询/
修改/取消。因此完整闹钟仍未交付。

## 已实现边界

- 使用固定 `api.proto` 生成的 `ListEntitiesServicesResponse`、`ExecuteServiceRequest` 和
  `ExecuteServiceResponse`，声明 response-only 的 `alarm_sync(request)`；没有手写消息编号、
  新开端口或关闭认证。
- 支持 `status/put/delete/enable/stop/snooze`，复用 v106 的参数校验、32 项容量、持久化回滚
  和乐观版本检查。业务拒绝返回固定错误并保持连接可用，未知 service key 不被误消费。
- 完整列表每页最多 4 项，保持在既有 8 KiB 帧边界内。HA 后续页携带首屏版本和精确偏移；
  版本变化、请求关联错误、页缺口、重复 ID、非法结构或未收齐记录均失败关闭，不发布半份列表。
- HA 通过绑定的 ESPHome 配置项 MAC 找到节点服务，不用可改显示名猜设备。实体状态是已确认
  闹钟数量，属性包含全部计划、启停、重复日、下一触发、响铃、时钟和同步状态。
- HA 修改默认携带当前确认版本；并发旧写会由 R1 拒绝。离线或超时不会覆盖上次确认缓存，
  也不会生成虚假成功确认。
