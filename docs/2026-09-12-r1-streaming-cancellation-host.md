# v92 O3 流式取消隔离主机记录（2026-09-12）

## 结论

提交 `6548f5c0b337857833f1778de81bb726f926bc88` 将内层家庭路由聊天日志的增量转发
限定在同一次受等待调用的生命周期内。取消、超时、失败或正常结束后，即使路由后台任务仍
保留旧聊天日志引用，迟到文字也不能再进入外层 Assist 的增量监听器和本轮 TTS 输入路径。

合成流式路由用异步门闩证明第一段文字到达外层监听器时，完整回答任务仍未结束；取消任务
后再从保留的旧聊天日志引用注入文字，外层监听器没有收到该迟到内容，会话映射和 busy 状态
也已清除。这通过了“增量先于全文完成”和“取消后旧增量隔离”的会话适配主机门槛。

本轮没有连接实际 HA、家庭路由、模型中心、ADB 或 R1，也没有安装 APK。外层监听器替身并
不等于真实 TTS 已产生首块音频或 R1 已开始播放，不能据此宣称端到端流式回答通过。

## 实现边界

- 不修改固定 HA 2026.8.2 的消息协议或私有路由实现；继续使用其聊天日志增量监听接口。
- 只有本次 `_delegate` 调用处于活动状态时才转发；`finally` 在所有退出路径关闭转发。
- 不尝试取消路由可能已脱离调用自行创建的后台计算；本地保证是隔离迟到输出，不虚报下游
  计算已经停止。
- 非流式路径、来源隔离的内层会话 ID、300 秒流式上限及原有失败清理语义保持不变。
