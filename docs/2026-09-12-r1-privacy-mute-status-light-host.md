# v115 强制软件静音与状态灯主机记录

## 结论

提交 `519ca9dc0a5d0a3822298cc362d3927704902087` 完成由中央实体键入口触发、设备本地持久且
HA/语音不可解除的隐私静音状态机，并增加固件3448两组灯节点的严格写入回读适配。代码和完整
主机门禁通过；本轮没有连接HA、ADB或首台R1。当前只能表述为代码支持，不能宣称特权权限、
真实采集停止、灯效或重启保持已在R1通过，更不能称为电气硬断麦。

## 静音入口与优先级

- 没有日历闹钟响铃时，中央键450毫秒内双击切换隐私静音；首击仍立即执行当前声音停止，不因
  等待第二击而破坏停止时延。计时器响铃时单击只停止计时器，不会留下静音双击窗口。
- 日历闹钟响铃时原有单击停止/双击稍后提醒优先；长按仍为原厂配网。静音手势不改变这两个
  v114映射。
- 静音状态先原子写入应用私有持久配置，再关闭当前Noise连接并销毁持有`AudioRecord`的运行时；
  写入失败不应用瞬时静音。服务重建时先读取静音，静音状态下只创建管理会话，不启动监听。
- HA只发现只读`object_id=microphone_privacy_muted`二进制传感器；Native API没有对应command，中文链路也
  没有解除入口。shell本地管理面只有受root/shell UID约束的按键事件注入，用于自动实机复核，
  没有直接`mute=false`操作。生产仍要求无公网ADB和无公开root入口。

## 状态灯与证据边界

- 代码使用已盘点的`multi_leds0/1`亮度节点，为关闭、失联、监听、处理、播放/响铃、配网、静音
  定义项目状态模式；这些是本项目映射，不命名为原厂标准。免打扰只压低普通状态，不弱化静音
  和配网状态。
- 每次状态变化写入两个节点后必须逐项读回精确值；权限拒绝、节点缺失或不一致均回报
  `privacy_led_not_confirmed`，并分别保留requested/confirmed状态，不能仅凭写调用宣称灯已亮。
- 历史v65已证明普通data APK没有灯节点写权限。因此v115实机验收必须核对签名安装身份、最小
  专用Enforcing SELinux/特权能力及真实节点回读；本轮主机实现不把该历史失败改写为通过。
