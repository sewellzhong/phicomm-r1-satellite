# v113 闹钟/计时器声音设置主机记录

## 结论

提交 `0dfe815066ae1cfcbcd8b64265af726b241a2f7d` 为 R1 本地闹钟增加每项独立的铃声和音量，
并为标准计时器增加共用的 Native API 配置实体。代码、协议替身和完整主机门禁通过；本轮未连接
HA、ADB 或首台 R1，真实扬声器音型、音量、抢占、重启持久化及资源释放仍待自动实机验证。

## 已实现

- 闹钟持久 schema 从 1 升至 2，并可读取旧 schema 1；旧记录迁移为 `classic`、100%。每项接受
  `classic`、`gentle`、`urgent` 三种本地合成音型及 1～100% 相对铃声音量，非法值零写入。
- Noise 认证的 `alarm_sync`、HA 全量实体、乐观版本、分页回读和离线待同步均包含铃声与音量；
  schema 1 待同步记录在读取时补默认值，重连冲突比较不会静默丢掉声音设置。
- 中文完整句入口可按唯一名称设置铃声或音量，查询会回报确认/待同步状态、音型和音量。失败、
  离线及同名歧义仍不反馈成功。
- 计时器公开标准 `number.timer_volume` 与 `select.timer_ringtone`，设备私有设置持久保存；中文可
  查询和修改，HA 命令后必须等实体状态回读才确认。计时器和日历闹钟仍分别持有响铃所有权。
- API 22 输出继续是 PCM S16LE、16 kHz、单声道；三种音型在设备本地实时合成，不依赖网络、
  URL 或私有音频素材。铃声音量与全局扬声器音量相乘，不篡改保存的全局音量。

## 动态到时提示边界

每项状态确定性生成 `prompt_text`（例如“吃药时间到了”），同时强制回报
`prompt_mode=tone_only`。当前 R1 只播放所选合成铃声，尚未离线朗读该文字；HA 校验器会拒绝把
其他模式伪装成已支持。要完成动态中文播报，后续须实现并验证可离线持久、许可证可审计且不依赖
到时联网的音频生成/传输方案。在此之前不能把 `prompt_text` 的存在写成动态语音已经播放。
