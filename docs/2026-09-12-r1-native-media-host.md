## 本轮实现

- 将原来只用于 TTS 格式协商、功能标志为零的 Native API 媒体实体升级为
  `r1_media_player`。实体仍保留 16 kHz、单声道、S16LE WAV 的公告格式协商，新增普通
  URL 播放、暂停、继续、停止、音量设置/增减能力；消息编号仍完全来自固定
  ESPHome 2026.8.0 `api.proto` 生成代码。
- 普通媒体 URL 只从 Noise 认证连接接收，限制为不含用户名、密码和片段的 HTTP/HTTPS，
  长度上限 2048。URL 不进入诊断状态或日志；空命令、非本实体 key、非零 device ID、
  非有限音量、越界音量和未声明命令均拒绝，不把请求到达写成播放成功。
- Android 5.1/API 22 后端使用系统 `MediaPlayer.prepareAsync()`。只有实际 prepared 后启动
  回调才进入 `playing`，暂停后才进入 `paused`，完成/停止/释放后进入 `idle`；异步错误只
  以有界错误码和计数进入本地诊断，协议无错误状态时对 HA 回报 `idle`，不伪造正在播放。
- 新 URL 原子替换旧播放器，完成、错误、停止和连接关闭均释放 `MediaPlayer` 与音频焦点。
  播放器音量使用既有 R1 持久百分比，HA 状态回报同一确认值。
- 普通媒体与语音、主动播报、计时器/日历闹钟使用可嵌套的抢占标记。系统抢占只暂停一次，
  所有抢占解除且音频所有者空闲后才恢复；用户明确暂停或停止会清除自动恢复意图，不能被
  后续 tick 复活。免打扰不阻止用户主动发起的普通媒体。
