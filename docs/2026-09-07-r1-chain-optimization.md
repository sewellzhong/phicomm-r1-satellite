# R1 全链路优化分析与开发任务（2026-09-07）

状态：优化已纳入开发。v64 已实现 O1/O2 的首个主机可测基础，包括有界取消/播放事件、显式取消阶段、先本地停止后协议线程单次取消、迟到事件隔离、播放器单次停止及完全释放门槛。v89进一步把固定Alexa模型用于回复处理/播放期间的新唤醒检测，并在旧运行及播放器完全结束后开启新命令窗口；中央键短按也已接入统一取消。v90补齐直接插话的主机路径：VAD/能量持续起音、只作用于检测副本的播放参考否决、单次`DIRECT_SPEECH`取消、5秒有界PCM交接和旧运行/播放器释放后新运行接续。v91开始O3主机实现：只有绑定路由真实声明流式能力时才对Assist报告支持，并把来源隔离内层会话的增量文字透传给流式TTS；非流式路径维持原行为，流式绝对上限为300秒。v92将增量转发限定在当前调用生命周期，合成门闩证明首段先于全文完成并隔离取消后的迟到文字。v93进一步通过固定HA 2026.8.2的真实Assist管线、流式阈值、TTS消息流和确定性PCM播放替身证明首个播放写入早于全文完成，取消后无迟到播放写入。代码和主机测试不等于R1或真实后端通过；实际TTS/HTTP/R1播放、新唤醒、直接插话、至少60秒真流式回答及工具确认边界仍待自动链路验证。未连接实际 HA/ADB；设备保存值、家庭路由和模型中心实时能力不能由模拟结果推定。

本文件集中维护 O1～O8 的分析、依赖与交付要求；产品需求见[功能盘点](2026-09-07-r1-feature-requirements.md)，架构和量化指标以[技术方案](../斐讯R1语音卫星技术方案-2026-08-27.md)为准，当前排期以[README](../README.md)为准。代码支持、主机模拟通过、实机验收通过分别记录。

## 1. 架构判断与证据分类

保留 R1 本地 Alexa/VAD、HA 中文 STT/对话/TTS、ESPHome Native API＋Noise 的分工。当前不增加平行语音协议、接入网关或 R1 中文 STT/LLM。HA 进程内包装层不等于额外网络服务；保留输入保护、确定性设备设置、权限校验及实际播放排空边界。

| 结论类别 | 当前依据与判断 | 对应任务 |
| --- | --- | --- |
| 已确认的实现缺口 | v90已有直接插话主机路径，但播放残留误取消、原厂帧接续及真实播放器释放尚无自动实机证据；多种声音来源尚无完整统一调度 | O2 |
| 部分主机实现 | v91已补齐流式能力门禁和隔离内层会话到Assist TTS的增量透传；PCM分块接收及模拟增量仍不能代替真实模型、家庭路由、工具结果和扬声器的端到端证明 | O3 |
| 已确认的实现形态 | 设置通过实体调用和数值回读确认，仍需覆盖旧值相同、状态过期及并发写入 | O4 |
| 需核验的兼容风险 | R1 与原生会话适配保留约 900 秒关联；旧模型中心参考代码曾用 120 秒，不代表当前部署一定不一致 | O5 |
| 已确认的版本耦合 | HA 适配使用私有卫星方法、内部管线集合和会话内部状态；升级故障是风险，非本次观察到的故障 | O6 |
| 需测量的性能问题 | 尾部静音默认 1.8 秒；STT、模型、TTS 与播放启动各占多少耗时尚无本次测量 | O1、O7 |
| 需测量的性能问题 | 动态 TTS 使用 FFmpeg；32 KiB 播放环形缓冲约容纳 1 秒 PCM，但播放器不等待填满，固定 HA 发送端已有节流，不能据此断言慢或必然溢出 | O8 |

## 2. 开发任务与交付要求

以下均为后续工作。任务编号用于需求、PR 与验证记录关联，不表示建立独立网络接口或全部必须单独重构。

| 编号 | 归属、时机及依赖 | 必须交付的行为 |
| --- | --- | --- |
| O1 分段诊断 | 系统诊断；随相关功能从开发初期加入 | 用运行关联 ID、各端单调时钟和结果码记录起音、输入结束、STT、路由/模型首段及完整结果、TTS 首块、播放写入/排空、续听与取消；记录缓冲高水位、欠载和诊断开销。默认不保存音频、正文或凭据，容量有界 |
| O2 音频控制与取消 | 统一播放基础；先于流式、媒体/蓝牙、闹钟和播报的完整接入 | 统一播放所有权、抢占、停止和恢复。按键停止、新唤醒、直接插话分别实现并验证；先停止本地声音和旧队列，再向 HA/TTS/模型传播取消，隔离迟到事件。用户明确停止的媒体不自动恢复，已执行设备动作不因停止回答而撤销 |
| O3 真流式回答 | 播放功能；依赖 O2，结合 O1/O5/O6 | 打通模型中心→家庭路由→R1 会话适配→TTS→播放的增量路径，以中文可朗读短句组织首段与后续段；首段播放时后续可继续生成。工具处理可提示进行中，结果确认前不得播报已完成；取消、超时和生成失败均能终止旧输出 |
| O4 配置确认 | 双入口设置及闹钟同步；结合 O1 | 区分请求、设备应用结果和实际状态。标准实体检查连接与状态新鲜度，旧缓存等于目标值不足以证明本次成功；自定义同步操作关联请求及配置版本，处理重复和并发。查询区分当前确认值与离线前记录值 |
| O5 会话协调 | 随流式与会话管理实现；结合 O2/O3 | 分别定义续听窗口、对话记忆、待确认操作的归属、有效期和清理规则；核验实际模型中心版本与期限，取消/异常不得残留可误用的确认状态。保留来源隔离和权限，不全局把“好”视为确认，不直接统一延长 TTL |
| O6 HA 兼容适配 | 随相应功能改动整理 | 集中固定 HA 版本私有接口依赖，加载时检查能力，不兼容明确报告；优先事件通知，定时刷新仅作补偿。适配卸载恢复所替换行为；有适用公开接口时迁移，不为整理而重写 HA Core |
| O7 端点与延迟 | 最终候选功能/数据/链路回归及其修复闭环；依赖 O1 | 使用固定输入、协议事件、状态回读和单调时钟验证超时、截断、取消及迟到数据隔离；不再要求用户真人控制停顿或主观判断体验 |
| O8 TTS 与缓冲 | 随 O3 做必要主机/最小实机检查，最终版本统一验收；依赖 O1 | 测量 FFmpeg 启动、重复转换、欠载和高水位后决定优化。仅在语速为 1.0 且格式已满足下游要求时评估直通；保留正确区分语速的缓存，不盲目扩大队列或新增常驻转码服务 |

音频优先级沿用功能需求：闹钟抢占普通媒体、免打扰过滤普通通知、主动唤醒及其回复和闹钟按例外规则允许；物理静音不得被任何入口绕过。新增播放来源必须接入同一停止/恢复策略，不各自维护相互冲突的音频生命周期。

### HA 外部依赖与接口边界

R1 仓库负责 Android 运行、原生协议与 `r1_input_guard`；家庭路由和模型中心由对应 HA 项目负责。O3/O5 必须交接增量文字、完成/失败、取消、会话来源/期限和工具执行结果的行为约定，并记录两侧受测版本。未知能力列为待核验，不把替身测试当作真实后端已支持。

公开仓库不复制私有路由源码、配置或凭据；兼容测试使用公开行为契约，私有源码验证单独记录。此处不定义新消息编号；继续固定协议版本并生成消息，优先标准能力，确需扩展时在对应任务中设计受认证接口。O4 不假定标准 Number 消息已包含请求 ID。

取消须区分“已请求”“下游已停止”“仅本地隔离”；后端不支持取消时明确限制并丢弃旧输出，不宣称计算任务已停止。旧任务不得影响新会话状态或重复执行设备操作。

## 3. 纳入现有开发顺序

1. 保留硬件入口及热点/蓝牙可行性为当前入口。无设备环境继续可独立开发的部分，未知硬件能力单列，不自动连接 HA/ADB。
2. 统一播放与停止基础纳入 O2；O1 随功能加入，O6 随被改动的 HA 代码整理。随后完成 O3 及相关 O5，再接入主动播报和媒体。
3. 本地闹钟/计时器、免打扰及双入口管理纳入 O4，并复用 O2；完成硬件、手机配网、蓝牙音箱及系统更新恢复，沿用既定路线。
4. O8随流式记录和评估。功能齐备后进行最终功能/数据/链路自动回归，按O1数据处理O7及其他发现的问题，再进行网络/IP恢复，最后进行72小时稳定性验收。修改候选版本后回归受影响项。

不恢复意图/真人语音体验调试，不重启KWS训练、选型和专项声学测试，不扩大多台、同步音乐或左右声道范围。“是→4”、理解偏差、历史误触发和“好”等真人结果保留为历史诊断，统一标记用户跳过/未验收。

## 4. 验收与现有差距

| 任务 | 主机/合成检查 | 最终实机或真实后端证据 |
| --- | --- | --- |
| O1 | 关联、时间口径、有界记录与异常清理；不泄露正文或凭据 | 诊断开销、音频帧预算和实际播放时序；不同设备时钟未经校准不直接相减 |
| O2 | 取消时序、迟到音频/事件隔离、抢占/恢复、重复停止 | 按键、新唤醒、直接插话分别测量；用户停止的媒体不复活；闹钟/通知/媒体共存 |
| O3 | 模型增量与 TTS 输入传递、生成/工具等待、失败和取消 | 至少 60 秒边生成边播放，无丢句、重播、卡死；证明首段播放早于全文生成，而非仅 PCM 分块 |
| O4 | 旧值相同但离线、过期状态、重复/并发写入和重连收敛 | 语音/HA 双入口结果一致，失败与待同步如实反馈，重启持久化 |
| O5 | 各层过期、来源隔离、普通“好”与待确认操作、异常清理 | 受测实际后端的连续对话及确认行为；旧短句失败单独复测，不由模拟覆盖 |
| O6 | 固定版本接口存在/变化/缺失、加载卸载恢复、事件和轮询 | 对应 HA 版本加载及设备状态同步，旧组件升级结论不继承 |
| O7 | 端点策略边界与时间统计（实施调整时） | 短句、慢速表达、停顿和最终延迟，维持第 14 章指标 |
| O8 | 直通/转换格式、缓存区分语速、流结束与部分写入、缓冲压力 | 首音、音调/语速、欠载/高水位、长回答与取消效果 |

**已知差距：** 当前 `NativeSettings` 尾部静音默认 1.8 秒，而技术方案第 14 章正常句末目标为 0.5～1.2 秒，语音结束到 STT 完成 P95 目标为 ≤1.5 秒。默认配置与目标存在差距；本次既不改参数，也不降低指标或宣称通过。O7 以最终实际设置和测量闭环，设备保存值须实读。

分段耗时用于定位，不以阶段耗时之和冒充可重叠的端到端耗时；区分模型首段与全文、首块写入与实际发声、流结束与硬件排空。沿用第 14 章的首音、停止/插话及稳定性指标，不新增无证据的性能保证。

每次交付在[实机清单](device-validation.md)记录任务编号、完整源码提交、APK SHA-256、HA Core 与相关自定义组件/后端版本，以及主机和实机结果。文档纳入不构成这些场景的测试证据。
