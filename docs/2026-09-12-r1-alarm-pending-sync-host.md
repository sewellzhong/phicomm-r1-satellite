## 同步与冲突边界

- HA 私有原子 Store 最多保存 32 个闹钟的基线和目标状态；同一 ID 的连续操作压缩为一个
  目标，新建后再删除或修改后恢复原值会消除该待同步项。
- 实体继续保留最后确认的 R1 列表，另以 `pending_changes`、`pending/conflict` 和明确错误
  展示未送达状态。损坏或超界的持久数据失败关闭，不猜测或部分加载。
- 重连先收齐同一 R1 版本的完整列表，再对全部待同步项做无写入预检。远端仍等于离线前
  基线时才提交目标；远端已经等于目标时按幂等成功清理；任何一项出现第三种状态时，本轮
  对所有项目保持零写入并锁定冲突，避免已取消闹钟复活。
- 预检通过后，每次设备确认都会更新完整列表，下一项使用新的全局版本。中途传输再次中断
  时保留未完成项；设备业务拒绝会锁定当前项，后续轮询不重复写入。
- `alarm_pending_discard` 是明确的本地冲突处理动作，可按 ID 或全部丢弃待同步目标；它本身
  不修改 R1。之后仍须重新回读设备，不能把丢弃动作解释为设备同步成功。
