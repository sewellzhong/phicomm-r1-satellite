# v104 本地计时器主机实现记录

日期：2026-09-12

## 结论

v104 在 v103 主动播报基础上实现固定 ESPHome 2026.8.0 的标准
`VoiceAssistantTimerEventResponse` 计时器事件，并在完整行为落地后把语音能力从 21 更新为
29，即新增 `TIMERS`。源码提交为 `c03084709d932fa263ea760e75f922d1d27f48af`。

倒计时由 R1 服务级控制器持有，而不是依赖当前 HA 连接或单次语音会话。已确认的 started、
updated、cancelled 和 finished 事件使用 Android 私有原子存储，活动计时器上限为32个；进程运行
期间使用单调时钟，服务或整机重启后使用可信墙钟扣除离线时间。墙钟不可信或倒退时保持
`clock_pending`，不提前响铃或假报正常，时钟恢复可信后从保存的剩余时间继续。

本轮只完成代码和主机测试，没有连接 HA、ADB 或 R1，没有安装 APK。标准事件实际到达、
API 22 私有存储、真实重启恢复、扬声器响铃、中央键停止及音频抢占仍须在首台自动验证；
不能把本记录写成实机计时器通过。设备仍运行 v102 APK，v103 主动播报也仍待实机验证。

## 行为边界

- started/updated 会创建或替换同 ID 计时器，支持活动与暂停状态；cancelled 删除计时器，
  finished 立即进入响铃。空 ID、控制字符、异常时长、超过32个活动计时器和损坏持久化状态
  均失败关闭。
- 本地到期不依赖 HA 在线；以 PCM S16LE、16 kHz、单声道实时合成 880 Hz 间歇铃声，
  不依赖公网 URL、原厂私有素材或仓库外提示音。
- 响铃前立即停止本地回答；若主动播报正在播放，播放器先停止，再由协议所有者线程回报
  播报失败，Noise 发送仍保持单线程。
- 中央键短按和仅限 root/shell 的 `timer-stop` 停止当前全部响铃，不取消仍在倒计时或暂停的
  计时器。`timer-status` 回读活动列表、剩余秒数、暂停/待校时状态及有界计数，不包含凭据。
- 已停止的到期 ID 使用最多64项的持久墓碑去重，避免 HA 重连补发 finished 后重复响铃；同 ID
  的新 started 事件会清除旧墓碑并开始新一轮。
- 铃声输出须等待旧播放器在5秒内释放；失败记录固定错误并每5秒重试，不在输出未建立时
  宣称响铃成功。服务销毁会停声，但保留持久状态供下次启动恢复。
