# R1 硬件、配网与蓝牙能力探测（2026-09-07）

本轮按当前开发顺序对 r1-sample01 做最小现场探测。设备仍运行 v63，固件 3448 / API 22，卫星状态为 `listening`，原厂音频包保持隐藏，真实录放音健康状态仍为通过。本轮没有安装 APK、恢复原厂包、连接或修改 HA，也没有保存音频。

## 现场结果

| 项目 | 结果 | 证据边界 |
| --- | --- | --- |
| 中央键 | `/dev/input/event0`，键值 `0x00c3`；短按实测 160 ms，长按实测 3110 ms | 原始事件已确认；尚未绑定停止、静音或配网动作 |
| 音量环 | `/dev/input/event1`，`BTN_TOUCH` 加 0～255 环形位置；顺时针递增、逆时针递减，跨零连续 | 定点轻触两次均无事件；按相对旋转手势处理 |
| 后台读取前提 | event0/event1/event3 均为 `0666`，SELinux 类型为 `input_device` | 文件权限允许读取；APK 域能否实际打开仍须安装后验证 |
| 音量一致性 | 手势改变 Android 媒体音量至 6/15，卫星逻辑音量仍为 10% | 证实当前存在双值偏差，须由卫星后台统一收敛 |
| 灯光 | 两组 `multi_leds0/1`，各为 0～4 级；普通 APK 对 brightness 无写权限 | 未找到公开灯光服务；不修改权限、不提权，保持待验证/可能阻塞 |
| 蓝牙音箱 | 固件运行 `A2dpSinkService`，同时存在 GATT 服务 | 服务存在不等于可配对或可播放 |
| 手机发现 | 当前安卓和 iPhone 均未发现 R1 | 蓝牙已开启但未处于可发现窗口；不能据此判定 A2DP Sink 失败 |
| 配网基础 | Android 5.1 Wi-Fi 状态机含 AP 状态，固件声明 BLE | 普通 APK 的旧热点反射权限及 BLE 广播能力须用限时探针验证 |

输出已避免记录家庭 SSID、硬件地址和凭据。完整语音回归、断网/IP 恢复和 72 小时稳定性验收仍暂停。

## v65 实现

v65 增加固件 3448 的 16 字节 ARMv7 `input_event` 解码、后台中央键/音量环监听、5% 逻辑音量步进，以及 shell 专用能力管理入口。中央键本版只记录短按/长按，不提前决定产品动作。蓝牙可发现、BLE GATT 广播和 WPA2 热点网页均为最长 120 秒的能力窗口；热点在服务重启时按持久恢复标记关闭并恢复原 Wi-Fi。

设备能力输出只报告布尔状态、计数和通用失败码。热点测试凭据仅在启动请求的 shell 响应中临时返回，不写入配置、日志或证据；网页不接收家庭 Wi-Fi 凭据。灯光仅报告普通 APK 是否可写，不尝试 chmod、root 或系统包替换。

主机测试覆盖短按/长按、方向、255↔0 回绕、静止触摸、部分读取、截断事件及 CLI 时限。本版部署和各限时窗口的真实结果另行记录，代码支持不作为实机通过。
