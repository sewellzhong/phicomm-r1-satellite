# v106 本地闹钟内核主机实现记录

日期：2026-09-12

## 结论

v106 在 v104 本地计时器及 v105 自动实机验证工具之后，新增首台 R1 的本地日历闹钟内核。
闹钟配置、下次触发、稍后提醒和正在响铃集合由服务级控制器持有，并使用 Android 私有
`SharedPreferences.commit()` 原子保存；到时调度不依赖 HA 连接或网络在线。
源码提交为 `d75b88f6b43f9a91a221373073d0bc244cb0e2eb`。

本轮是本地内核增量，不是完整闹钟交付。HA 全量展示、认证同步扩展、中文语音创建/查询/
修改/取消和实体按键“停止/稍后提醒”产品映射仍未实现；代码也未连接 HA、ADB 或 R1，不能
把主机测试写成实机响铃、重启恢复或 API 22 持久化通过。设备仍运行 v102 APK。

## 已实现边界

- 最多保存 32 个闹钟；支持 `YYYY-MM-DD` 单次日期或 Monday=bit0 至 Sunday=bit6 的每周
  重复，两种计划互斥。每项包含稳定 ID、名称、时分、启停、默认稍后提醒分钟数、下次触发、
  本项修订号；列表带全局单调版本。
- 使用设备当前时区计算本地日历时间。时区变化会重算下次触发；墙钟不可信时进入
  `clock_pending`，不提前响铃或假报正常，时间恢复后重新调度。
- 到期后 5 分钟内允许补响；超过窗口记录 `missed`，单次闹钟自动停用，重复闹钟直接调到
  下一有效日期，不逐秒追赶多周旧事件。断电期间无法响铃的边界保持明确。
- 单次和重复闹钟均支持停止与 1～60 分钟稍后提醒。触发集合、最后触发时刻和稍后提醒期限
  随配置持久化，重启后可恢复正在响铃状态并避免同一次计划重复触发。
- 配置写入支持 `expected_version` 乐观并发检查。非法 ID、控制字符、日期、时分、重复位、
  容量和过期单次计划均拒绝；配置持久化失败会恢复内存旧值并向调用方报错，不反馈成功。
- 本地闹钟与标准计时器共用现有 16 kHz 单声道合成铃声和音频抢占门槛，但分别持有播放
  所有权：停止一类不会误停仍在响铃的另一类。服务销毁才释放全部所有者。
- root/shell 限定的本地管理接口新增 `alarm-status`、`alarm-put`、`alarm-delete`、
  `alarm-enable`、`alarm-stop` 和 `alarm-snooze`。状态只包含计划、版本及有界计数，不含凭据。
