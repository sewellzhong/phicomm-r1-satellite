# 真人功能验收与多台部署现行计划

## 现行决定

自 2026-09-14 起恢复真人语音功能验收，并把后续部署范围规划为 3～8 台 R1。2026-09-16 进一步确认此前 R1 麦克风曾朝下摆放，受影响的方向、距离、声学和体感结果必须在麦克风朝上的正确姿态下重新验收。执行顺序固定为先完成 `r1-sample01`，再接入其他设备；本决定替换此前“真人验收停止”和“仅首台 R1”的开发范围，但不删除历史结果，也不使任何设备自动继承 `r1-sample01` 的结论。详见[姿态纠正与真机验收恢复决定](2026-09-16-r1-repositioned-microphone-revalidation-plan.md)。

真人验收采用自然真人操作与受控声学诊断相结合的方式。固定话术、位置、距离和音量用于可复现诊断；在麦克风朝上、姿态和条件完整记录后，方向、距离、唤醒率、识别率、AEC/DOA 和主观听感恢复为首台真机验收项目，结果仍须与自动功能/数据/链路证据分开记录。

## 设备与身份边界

每台设备必须单独建立 serial、3448/API 22、固件 fingerprint、Enforcing 状态、APK 哈希、音频代理状态、恢复基线和证据目录。每台使用独立 Noise 身份、设备 ID、HA 注册实体和回滚记录，不复制首台运行时状态或凭据。

公开清单只保存摘要和脱敏证据路径。Noise PSK、Wi-Fi 密码、HA 长期令牌、完整备份、签名私钥和家庭语音不进入仓库。

`tools/validation/validate-fleet-manifest.py` 校验 3～8 台清单、设备身份唯一性、APK/Noise 摘要格式、证据路径和凭据字段拒绝；它不执行刷机、安装、配网或 HA 注册。

`tools/validation/validate-single-device-release.py` 是多台阶段的唯一解锁门禁；它要求首台真人功能、自动回归、配网、更新回滚、网络/IP恢复和72小时稳定性全部为 `passed`，否则拒绝进入多台接入阶段。

`tools/validation/validate-voice-functional-evidence.py` 校验脱敏真人/自动结果，只接受功能案例状态和有限失败码，拒绝 transcript、录音路径/数据及凭据字段。`natural_functional`、`controlled_diagnostic` 和 `automated_state` 三种模式不会互相替代。

首台音频所有权的下一项自动入口为 `tools/native/validate-timer-media-ownership.py`：它覆盖标准计时器到期抢占媒体、停止后条件恢复，以及用户先停止媒体后不复活。该工具只在首台阶段运行，不解锁多台阶段。

## 验收顺序

1. `r1-sample01` 完成功能级真人回归：Alexa 唤醒、中文 STT/意图/TTS、流式回答、播放中打断、主动播报、计时器、闹钟、媒体、免打扰和软件静音。
2. 在同一最终候选上完成首台自动回归、配网、更新回滚、网络/IP恢复和72小时稳定性，并生成首台 release gate；门禁未通过时停止，不创建或消费多台清单。
3. 首台门禁通过后，其他设备逐台完成身份/恢复/签名候选/音频数据链自动检查，再逐台执行真人功能和失败回滚验证。
4. 全部单机通过后执行 3～8 台并发 HA、音频所有权、网络、资源和重启回归。

真人结果分为 `natural_functional`、`controlled_diagnostic` 和 `automated_state`，不把诊断或主机结果改写成实机功能通过。
